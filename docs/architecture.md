# life_robot 架构设计

> 入口：[`../commen_readme.md`](../commen_readme.md)。本文件只写「为什么」与跨层规则；
> 分层表、状态所有者、TF 所有者、安全链、演进路线已在总纲 §2–§3/§6，不重复。

---

## 1. 设计原则

| 原则 | 含义 | 反例 |
| ---- | ---- | ---- |
| 单一职责 | 一个包/节点只做一件事 | 一个节点既检测又发 `/control/*` |
| 契约先行 | 先定消息与语义，再写实现 | 私有 dict 跨进程传数据 |
| 单向依赖 | 只允许高层依赖低层 | 驱动 import 决策模块 |
| 状态收敛 | 同一状态只有一个所有者 | 三个模块各自维护 TCP 位姿 |
| 控制单出口 | 只有 L6 发控制指令 | L5/L7 直接 `ros2 topic pub /control/move_p` |
| 显式失败 | 失败必须上报，不静默吞掉 | 超时后假装成功 |
| 可取消 | 长任务必须是 action | 用 topic 发长任务 |
| 配置外置 | 参数进 yaml/launch | 速度、TCP 偏移写死源码 |
| 自包含 | 规则与命令在 `life_robot/` 内闭环 | 依赖外部项目文档作为权威 |

## 2. 通信

### 2.1 原语选择

| 场景 | 原语 |
| ---- | ---- |
| 周期反馈（关节/位姿/图像/状态） | topic |
| 低频查询/一次性请求 | service |
| 长耗时、可取消任务 | action（goal/feedback/cancel/result） |
| 参数 | ROS 2 parameter / yaml |
| 大块静态数据（地图/标定） | 文件 + 路径参数 |

禁止：用 topic 表达需要成功/失败确认的长任务；用 service 做高频控制或阻塞 >100 ms；
用 action 传周期流；用 `std_msgs/String` 拼 JSON 做结构化契约。

### 2.2 控制单写者

- `/control/*` 正常运行时只由 **L6 motion** 发布。
- L5/L7/L3 不得发布；调试脚本例外，必须显式标注且默认不纳入 bringup。
- 多目标并发由 L6 仲裁，禁止两个节点同时写控制话题造成抖动。

### 2.3 命名与消息语义

- 话题：`/<模块>/<语义>`，全小写+下划线；驱动沿用 `/control/*`、`/feedback/*`。
- 动作：`/<模块>/<动宾>`，如 `/decision/execute_task`、`/motion/move_to_pose`。
- 所有跨层消息第一行 `std_msgs/Header`（需要时间/坐标系时）。
- `header.stamp` = 采集/生成时刻；`header.frame_id` = 数据所在坐标系。
- 位姿用 `PoseStamped`，关节用 `JointState`（`name` 与 URDF 一致），健康用 `DiagnosticArray`。
- 目标必须可表达：位姿 + 约束 + 超时 + 优先级 + 任务 ID。

## 3. 状态与一致性

- 状态所有者与对外接口见总纲 §3.2；本文件只强调三条：
  1. 其他模块**只能订阅/查询**，不得各自维护副本后写回。
  2. 到位判断由 L6 基于 L1 最新反馈完成；L5 不缓存关节角自判。
  3. L3 只给观测；融合、去重、生命周期归 L4；L5 每次任务前查询新鲜度。

- L4 是**汇聚点**不是调度点：只被动接收/回答，不主动指挥。
- L6 可只读 L4（障碍/目标），不得写 L4。
- L8 可启停所有节点，但不得替各层做运行时决策。

## 4. 坐标系、时间与 QoS

### 4.1 TF

- TF 段与发布者见总纲 §3.3；**同一 `parent → child` 只能一个发布者**。
- 标定结果落盘 `config/calibration/`，启动加载，不写死代码。
- 位姿消费方负责 `tf2` 转换；发送方不猜消费方坐标系。

### 4.2 时间

- 使用节点时钟；仿真 `use_sim_time:=true`。
- 时间戳在采集/生成时打，不在发布时补；超时判断用单调时钟。
- 超时、周期、重试全部参数化；禁止业务代码 `time.time()` / `sleep()` 做逻辑。

### 4.3 QoS

| 数据 | Reliability | Durability | Depth |
| ---- | ----------- | ---------- | ----- |
| 传感器流（图像/点云/IMU） | Best Effort | Volatile | 1–5 |
| 关节反馈 / TCP | Reliable | Volatile | 10 |
| 控制指令 | Reliable | Volatile | 1–10 |
| 诊断 | Reliable | Volatile | 10 |
| 静态地图/标定 | Reliable | Transient Local | 1 |
| 任务/事件 | Reliable | Volatile | 10 |

- 发布/订阅 QoS 不兼容时优先改订阅方匹配；联调用 `ros2 topic info -v` 检查。
- 高频数据禁用 Transient Local。

### 4.4 实时性

- L1/L6 控制回路周期由驱动/SDK 决定（当前反馈默认 200 Hz）。
- L3/L4 允许延迟，但必须带时间戳，由消费方判断过期。
- L5 不参与硬实时；安全停止不依赖 L5，依赖 L1 看门狗 + 硬件急停。

## 5. 安全与失效

- 优先级：`硬件急停 > 驱动看门狗/限幅 > L6 可行性校验 > L5 任务互锁 > L7 人机互锁 > L8 监控`。
- 模式：`ESTOP`（无控制）/`MANUAL`（遥操作）/`AUTO`（仅 L5→L6）/`FAULT`（人工复位）。
- 失效原则：
  1. **可见**：超时/异常/断连必须发诊断或状态。
  2. **收敛**：控制失败→停止保持；感知失败→标记不可用并降级；决策失败→安全空闲。
  3. **不自动重试危险动作**：抓取可重试；碰撞/急停后必须人工确认。
  4. **取消彻底**：L6 停止轨迹并回到可控状态后再返回 `CANCELED`。
  5. **启动即安全**：默认保守速度、默认不自动使能（可配置）。

## 6. 运行时与部署

### 6.1 拓扑

```
[driver] ──/feedback/*──► [motion L6] ──/control/*──► [driver]
[perception L3] ──► [world_model L4] ◄── [decision L5] ──► [motion L6]
                                          ▲
                                     [applications L7]
```

### 6.2 命名空间与生命周期

- 单臂可用全局；多臂 `namespace:=arm_left/right` + remap，不改代码。
- 跨层公共接口 `/<模块>/...`；模块私有 `~/...`。
- 关键节点支持 SIGINT 干净退出；可选 lifecycle 先在 L1/L6 试点。
- 高层节点必须容忍低层未就绪（等待/重试），不假设启动顺序。

### 6.3 部署形态

| 形态 | 说明 |
| ---- | ---- |
| 真机 | 全节点本机/分布式 ROS 2 |
| 仿真 | mock 驱动 + Gazebo/Isaac + 同一套 L3–L7 |
| 回放 | rosbag 回放传感器/反馈，离线调试 |

**要求**：L3–L7 在真机与仿真之间不分叉；差异只在 L1/mock 与 L8 配置。

### 6.4 测试分层

| 层级 | 内容 | 手段 |
| ---- | ---- | ---- |
| 单元 | 纯算法/状态机 | pytest / gtest |
| 组件 | 单节点 IO | launch_testing / mock 话题 |
| 集成 | 跨层闭环 | 仿真 + 脚本化任务 |
| 硬件在环 | 时延/限幅/急停 | 真机受控场景 |
